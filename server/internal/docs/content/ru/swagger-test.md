# Тесты Swagger

Тест Swagger проверяет HTTP API по его спецификации Swagger/OpenAPI. Вы даёте agnts спецификацию, базовый URL, эндпоинты и, если API его требует, токен. agnts составляет проверки для каждого эндпоинта (основной сценарий, пропущенные и неверные поля, без токена и с неверным токеном, несуществующие id, края пагинации), отправляет настоящие запросы и выносит вердикт по каждой проверке — с запросом и ответом, на которых он основан.

## Как создать

Новая задача → **Тест Swagger**.

- **Спецификация**: адрес спецификации (`…/openapi.json`, `…/swagger.json`, `…/v3/api-docs`) или страницы Swagger UI, Springdoc или Redoc — agnts найдёт за ней спецификацию. Можно загрузить файл. Если для ссылки на спецификацию нужен вход (она отвечает 401 или 403), отметьте **Для ссылки на спецификацию нужен вход**. Выберите **Логин и пароль**, если ссылка их спрашивает (форма откроет это сама): они нужны только чтобы открыть ссылку, а запросы агента к API идут с токеном из раздела «Аутентификация». Или выберите **Токен**, если ссылка принимает токен; он же станет токеном API, если вы его не поменяете. Ничего из этого не сохраняется: всё уходит вместе с загрузкой только на хост спецификации. Swagger 2.0 и OpenAPI 3.0/3.1, до 5 МБ, одним файлом (другие файлы, на которые ссылается спецификация, agnts не загружает).
- **Базовый URL**: куда идут запросы. Сначала это сервер из спецификации, а он часто боевой — проверьте. Имя хоста или IP, любой порт.
- **Что тестировать**: напишите, какие эндпоинты проверить, и всё, что тесту нужно знать («только POST-эндпоинты в /v1/orders; пользователь 42 — тестовый»). agnts тестирует только написанное: запуск видит всю спецификацию, составляет проверки только для названных эндпоинтов и ничего не сообщает об остальных.
- **Выбрать эндпоинты (необязательно)**: сначала ничего не отмечено. Отметьте эндпоинты, чтобы проверить ровно их; **Рекомендуемые** отмечают все, кроме устаревших и GET, чьё название намекает, что они что-то меняют (`logout`, `export`, `send`, `reset`, `sync` …), и форма объясняет, почему они не отмечены. Тесту нужно одно из двух: текст или отмеченные эндпоинты.
- **Аутентификация**: нет, Bearer-токен, API-ключ в заголовке или в запросе, Basic. Берите токен **тестового аккаунта**, никогда не личный и не боевой.

## Только чтение и запись

По умолчанию тест **только читает**: отправляются только GET, HEAD и OPTIONS. «Только чтение» — не то же, что «безвредно»: некоторые API меняют данные и на GET, и решать это вам, когда вы отмечаете эндпоинты. Чтобы включить запросы на запись (POST, PUT, PATCH, DELETE), нужно подтвердить, что базовый URL не боевой. Тогда agnts выстраивает проверки как создание → чтение → изменение → удаление и удаляет то, что создал.

## Аккаунты и файрволы

Проверки «без токена» и «с неверным токеном» выглядят для файрвола как атака на вход. Запуск отправит не больше 3 таких запросов и остановится после трёх ответов 429 или ответа 401/403 на запрос с токеном. Тестовый аккаунт всё же может заблокироваться, а адрес — попасть в бан. За частной сетью этот адрес — VPN-подключение рабочего пространства, которым пользуются GitLab и другие тесты.

## Внутренние API

API на хосте из маршрутов частной сети рабочего пространства доступен через эту сеть, как GitLab. Любой другой хост должен указывать на публичный адрес: для хостов из тикета agnts отказывает во внутренних адресах.

## Результаты

Вкладка **Результаты API** показывает эндпоинты, сначала со сбоями. Откройте проверку, чтобы увидеть запрос и ответ, на которых основан вердикт, и скопировать его как curl (токен остаётся скрытым). agnts также сам сверяет каждый ответ со схемой спецификации; такие находки помечены **проверка agnts**. Вердикт без записанного запроса отбрасывается. **Запросы** — все запросы запуска.

- **Пройдено / Сбой**: проверка выполнена, ответ верный или нет.
- **Пропущено**: не выполнялась намеренно: запись выключена, нужных данных API не даёт, достигнут лимит.
- **Не выполнено**: не смогла выполниться: токен истёк или упал запрос, от которого она зависит. Если не выполнена ни одна проверка, запуск завершается ошибкой с причиной.

**Создать тикет Bug** превращает сбои в тикет Bug (в репозитории теста, если он есть). **Запустить снова** повторяет тест; закрытый тест запускается как новый тикет.

## Наборы

**Сохранить как набор** у завершённого теста оставляет его для повторных запусков: вручную, каждый час, каждый день или по понедельникам (в выбранный час UTC) или после каждого деплоя. Каждый запуск — новый тикет теста Swagger. Он берёт план прошлого запуска набора, поэтому повторы тратят гораздо меньше шагов, и сравнивается с ним: уведомление начинается со сбоев, которых раньше не было. Новый запуск не начнётся, пока идёт прошлый.

**Создать хук деплоя** даёт URL, который пайплайн деплоя вызывает командой `curl -X POST <url>` после каждого деплоя. Он показывается один раз; новый отключает старый. У набора своя копия токена, запечатанная так же, как у тикета, — до замены или удаления набора.

## Токен

Он запечатывается при сохранении формы, больше не показывается, удаляется из всего, что хранит agnts (журналы, результаты, отчёт, живые события), и стирается при закрытии тикета. Внутри запуска его читает только agnts-api — клиент, который отправляет запросы.

## Стоимость

Одна сессия Claude (Sonnet) не больше чем на 60 шагов, какой бы моделью ни программировало рабочее пространство: защита токена и API держится на страже agnts внутри запуска, а у запусков Codex его нет. Запросы уходят одним пакетом, 5 в секунду (настраивается), не больше 300 за запуск.
