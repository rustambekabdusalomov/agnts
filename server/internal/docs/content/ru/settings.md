## Ограничители

agnts-guard проверяет работу Claude внутри каждого запуска, по ходу дела; проверки agnts после запуска по-прежнему действуют. **Профиль** задаёт строгость: *Минимальный* отклоняет секреты и файлы .env, применяет правила команды с шаблоном и требует успешной сборки, прежде чем Claude закончит; *Стандартный* также отклоняет пропуск и удаление тестов, отключение линтеров и изменения конфигурации проверок, добавляет линтер в стоп-проверку и проверяет каждый изменённый файл; *Строгий* также запускает тесты в стоп-проверке, отклоняет проглоченные ошибки и удалённые проверки и для части задач просит у Claude факты (кто использует файл, как откатить разрушительную команду) перед первыми правками, чтобы сравнить в аналитике. Человек снимает одно ограничение для задачи, написав `agnts: allow skipped_test` (или другой вид) в задаче или ответе.

Здесь же: что делает agnts, если запуск **застрял** (отмечает или один раз просит Claude остановиться и подумать), **Доказывать исправления** (тест, который падает до изменения и проходит после), **Глубокое ревью** (проходы по безопасности, тихим ошибкам, тестам и типам; *Авто* — для большой или сложной работы), **Учиться на запусках** (советы из проблемных запусков) и модель **Второго мнения**, которая читает выбранный подход сложных задач. **Дополнительно** отключает отдельные хуки.

## Превью

Скриншоты каждого изменения интерфейса в репозиториях с командой превью, модель, которая выбирает страницы и оценивает их, можно ли запускам кода самим смотреть на приложение, и дополнительные хосты для контейнеров запуска (например staging API вашего приложения).

## Частные сети

Туннели в ваши сети для GitLab, Jira, Plane или реестра пакетов, доступных только через VPN. В рабочем пространстве их может быть несколько — по одной на компанию, офис или дата-центр. Для каждой выберите **agnts-link** (небольшой агент в сети: подключается сам, не требует данных VPN и пересылает вебхуки), **WireGuard** или **OpenVPN** (вставьте клиентский конфиг) и перечислите её маршруты: хосты, домены (.corp.local) или частные диапазоны, которые идут через неё. Соединение идёт через сеть, чей маршрут подходит к нему точнее всего: точный хост важнее домена, более длинный домен — более короткого, узкий диапазон — широкого. Две сети не могут указывать один и тот же маршрут; более узкий маршрут внутри маршрута другой сети допустим. Всё остальное идёт как раньше. Добавьте корпоративный CA сети, если у её хостов внутренние сертификаты, и проверьте кнопкой **Проверить**, через какую сеть идёт host:port, до подключения интеграции. Код, который agnts запускает по вашим задачам, может обращаться ко всем перечисленным хостам, поэтому указывайте только нужные.
