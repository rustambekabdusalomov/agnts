# Интеграции

Сервисы, с которыми работает agnts: Jira или Plane для тикетов и GitHub или GitLab для кода. У каждого своя страница со статусом подключения и настройками.

## Подключение

Вставьте токен доступа с указанными правами. Он хранится зашифрованным на вашем сервере и больше не показывается. «Проверить подключение» проверяет его в любой момент.

## Права

На странице git-сервиса видно, какие права есть у токена. Обязательные должны быть выданы, иначе запуски не сработают.

## Доступ к репозиториям

Отключите репозиторий, чтобы agnts не клонировал его и не отправлял туда изменения, не удаляя его.

## Коммиты и пул-реквесты

От чьего имени коммиты, строка Co-authored-by, формат заголовка, черновики, метки, ревьюеры и что происходит после слияния.

## Правила Jira

Какие проекты отслеживаются, метка, типы задач и статусы, которые берёт agnts, — в виде точного запроса.

Задача попадает в репозиторий, привязанный к её проекту (Репозитории → проект Jira). Чтобы отправить задачу в другой, добавьте метку repo:<имя> с именем репозитория в agnts, например repo:web; регистр не важен. Она важнее репозитория проекта, так что один проект Jira может вести несколько репозиториев, а самому проекту репозиторий не нужен. Добавленная или изменённая метка переносит тикет, пока работа не началась; после начала тикет остаётся в своём репозитории (его можно сменить на странице тикета, пока он в очереди или с ошибкой). Если agnts не знает такого имени, задача идёт в репозиторий проекта, а в истории тикета появляется предупреждение. При нескольких метках repo: учитывается первая.

Когда включено «Только задачи, назначенные мне» (по умолчанию), agnts берёт задачу с меткой, только если она назначена на аккаунт Jira, которым подключён agnts, и в запрос добавляется assignee = currentUser(). Задача, назначенная на другого или ни на кого, не создаёт тикет; уже созданный тикет по-прежнему получает обновления задачи. Выключите, чтобы брать все задачи с меткой.

## Plane

Plane Cloud или ваш собственный Plane. Укажите адрес API (https://api.plane.so или адрес вашего Plane), slug рабочего пространства из адреса Plane и персональный токен доступа. В Plane добавьте вебхук (Workspace settings → Webhooks) с адресом, показанным здесь, и событиями задач, затем вставьте секрет, который покажет Plane. Привяжите репозиторий к проекту Plane по его идентификатору (WEB в WEB-123) и ставьте на задачи метку agnts или agnts-<вид>. Пустые статусы переводят задачу в первое состояние подходящей группы (started, completed, cancelled); «на ревью» — только в состояние, которое вы укажете. Синхронизация раз в час подбирает вебхуки, которые Plane не доставил.

Чтобы отправить одну задачу в другой репозиторий, добавьте метку repo:<имя> с именем репозитория в agnts, например repo:web; регистр не важен. Она важнее репозитория проекта, так что один проект Plane может вести несколько репозиториев. Синхронизация и ежечасная проверка читают только проекты, привязанные к репозиторию, поэтому оставьте проект привязанным. Добавленная или изменённая метка переносит тикет, пока работа не началась; после начала тикет остаётся в своём репозитории. Если agnts не знает такого имени, задача идёт в репозиторий проекта, а в истории тикета появляется предупреждение.
